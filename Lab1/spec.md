# Вимога: 
зробити ER-модель на Mermaid для розуміння системи бронювання та оплати(купівлі) квитків на сеанси в кінотеатрі "Супутник"

# Сутності:
1. *Клієнт* - 
   - <u>Атрибути:</u>
   1. *Гроші
   2. Вподобання у жанрах
   3. Зацікавленість купити квиток
  
2. *Кінотеатр* - 
    - <u>Атрибути:</u>
    1. *Якість
    2. *Кількість місць
    3. *Ціни
    4. Спектр жанрів в прокаті
    5. Доступність
    6. Знижка по студентському
3. *Платіжна система*:
   - <u>Атрибути:</u>
    1. *Карта
    2. *Готівкою на касі
    3. *Система підтвердження платежу
    4. *Безпека транзакції
4. *Сайт для бронювання*:
   -  <u>Атрибути:</u>:
    1. *Наявність зручного інтерфейсу
    2. *Швидка робота сайту
    3. Привабливий дизайн
    
# Система зв'язків між сутностями:
1. Клієнт ||--|| Кінотеатр
2. Клієнт ||--|{ Платіжна система
3. Клієнт ||--o| Сайт для бронювання
4. Кінотеатр ||--|{ Платіжна система
5. Кінотеатр ||--o| Сайт для бронювання
6. Сайт для бронювання o|--|{ Платіжна система
# Критерії прийняття:
1. Ключові атрибути позначено знаком "*"
2. Система зв'язків чітко прописана, не треба вигадувати зайвого
3. Оформлення чітке, без накладання зв'язків одне на одного
4. Модель повинна бути в Третій нормальній формі(3НФ)
5. Використовувати виключно Mermaid(erDiagram)
6. Назви атрибутів писати в єдиному для всіх форматі(наприклад snake_case)
7. Без сполучних таблиць
8. Всі ID типізовані як "uuid"
