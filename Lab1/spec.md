# Вимога: 
зробити ER-модель на Mermaid для розуміння системи бронювання та оплати(купівлі) квитків на сеанси в кінотеатрі "Супутник"

# Сутності (оновлено):
1. *Клієнт* (Людина)
   - <u>Атрибути:</u>
   1. *ПІБ
   2. *Електронна пошта
   3. Баланс грошей

2. *Фільм* (Кінокартина)
   - <u>Атрибути:</u>
   1. *Назва
   2. *Жанр
   3. *Тривалість (у хвилинах)
   4. Вікове обмеження
  
3. *Зал* (Кінотеатру)
   - <u>Атрибути:</u>
   1. *Назва залу
   2. *Місткість
   3. Підтримка 3D

4. *Сеанс* (Розклад)
   - <u>Атрибути:</u>
   1. *Час початку
   2. Формат показу (2D/3D)

5. *Квиток*
   - <u>Атрибути:</u>
   1. *Номер місця
   2. *Ціна
   3. Статус оплати
    
# Система зв'язків між сутностями:
1. Фільм ||--o{ Сеанс (один фільм має багато сеансів)
2. Зал ||--o{ Сеанс (в одному залі проходить багато сеансів)
3. Сеанс ||--o{ Квиток (один сеанс містить багато квитків)
4. Клієнт ||--o{ Квиток (один клієнт купує багато квитків)
    
# Критерії прийняття:
1. Ключові атрибути позначено знаком "*" мають бути також так само позначені в таблиці( наприклад *Гроші)
2. Система зв'язків чітко прописана, не треба вигадувати зайвого
3. Оформлення зв'язків чітке, категорично заборонено накладання візуально зв'язків одне на одного
4. Модель повинна бути в Третій нормальній формі, у тому числі наявність зовнішніх ключів(3НФ)
5. Використовувати виключно Mermaid(erDiagram)
6. Назви атрибутів писати в єдиному для всіх форматі, не роби із себе дизайнера посеред форматування(виключно у snake_case)
7. Без сполучних таблиць
8. Всі ID без виключень повинні типізовані як "uuid"
